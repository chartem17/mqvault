# ADR 0013. MT5: настільний Bridge на ПК користувача (лише вихідний, лише читання)

**Статус:** запропоновано, чекає погодження власника · **Дата:** 2026-11-08 · Деталі й доказ безпеки — [features/mt5-bridge.md](../features/mt5-bridge.md)

## Контекст
Автосинхронізація MT5 була відкритим питанням (roadmap, «Автоматична синхронізація»): у MetaQuotes немає публічного хмарного API, а хмарні посередники вимагають investor-паролів і платні. Старий локальний міст (`127.0.0.1:8787`, вимкнено 2026-10-31, `f507917`) працював лише з локальним сайтом і відкривав порт. 2026-11-08 власник вирішив: синхронізація — через програму, яку користувач встановлює на ПК, «встановив і все», без налаштувань терміналу, і максимально захищено.

## Рішення
- Програма **MQVault Bridge** для Windows: Python + офіційний пакет `MetaTrader5`, приєднується до вже залогіненого терміналу через локальний IPC. Пароль не потрібен і не збирається. Налаштування MT5 не змінюються.
- Встановлення per-user, без прав адміністратора й служби; автозапуск при вході в Windows; supervisor + окремий worker на кожен термінал; локальна черга (outbox) — без втрат при офлайні.
- Зв'язок **лише вихідний HTTPS** з сайтом; жодного відкритого порту на ПК.
- Підключення пристрою — Device Authorization (RFC 8628): Bridge відкриває сторінку з кодом, користувач натискає «Підключити». Ключ пристрою ECDSA P-256 (TPM → CNG → DPAPI) не покидає ПК; на сервері лише публічний ключ. Кожен запит підписаний (метод, шлях, час, лічильник, хеш тіла); повтори відсікаються атомарним `last_seq`.
- Bridge **лише читає** (`account_info`, `history_deals_get`, `symbol_info_tick`); торгових викликів у коді немає, CI це перевіряє; у сервера немає каналу команд, крім фіксованого enum статусів.
- Пристрій може лише **записувати** сирі deals свого власника; читати журнал не може.
- Bridge пересилає сирі deals; угоди журналу будує сервер (`src/lib/bridge/deals-to-trades.ts`): час — за `broker_timezone` (ADR 0001), net/R — сервер (ADR 0003), дублікати — як ADR 0012; поля користувача (сетап, емоції, нотатки, розбір) синхронізація не перезаписує; видалене користувачем не воскрешає.
- Оновлення: Authenticode + маніфест, підписаний офлайн-ключем власника (не на Vercel/GitHub); заборона відкату версії; автоматичний відкат при збої.
- Старі `/api/mt5/*` лишаються 410; новий простір — `/api/bridge/*`.

## Наслідки
- Замінює рішення від 2026-10-31 «локальний міст відхилено» (`docs/local-bridge-retired.md` в історії `f507917`) — за новим рішенням власника.
- Потрібні: міграція (4 таблиці, окреме погодження), сертифікат підпису коду (витрати), офлайн-ключ оновлень у власника.
- До реалізації — прототип (етап 0) підтверджує, що `MetaTrader5` працює без налаштувань терміналу й що ліцензія дозволяє розповсюдження.
- Календар новин MT5 через Python API недоступний; Bridge його не передає.
