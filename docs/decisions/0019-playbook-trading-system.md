# ADR 0019. Playbook: торгова система власника, план угоди до входу, дисципліна угод

**Статус:** запропоновано 2026-11-14 (гілка `agent/ts-rules`; застосування міграції `20261114120000_trade_plans` — окреме погодження власника) · Доповнює ADR 0001, 0002, 0010, 0011, 0014, 0018. Аудит — [`../TS-RULES-AUDIT.md`](../TS-RULES-AUDIT.md).

## Контекст
Правила ТС власника (ліміти дня, торгові вікна в київському часі, «драбина» ризику 1 % → 0.5 % → 1 %, модель входу, ведення угоди) жили частково в стратегіях «Контролю стратегії» (перевірка після факту, по рахунку), частково в денному чеклісті без блокування, а здебільшого — ніде. Угоди потрапляють на сайт після факту (CSV з MT5, Bridge). Потрібен бар'єр **до** входу і чесна метрика «скільки угод за планом».

## Рішення
- **Один конфіг ТС** — `app_users.preferences.playbook` (`lib/playbook/config.ts`, `sanitizePlaybook`; без міграції). Усі числа ТС — лише там; null = значення за замовчуванням. Пояс ТС — параметр (`Europe/Kyiv`); у ньому читаються вікна й «день» лімітів ТС. Ринкові сесії ADR 0002 не змінюються — вікна ТС є окремим поняттям.
- **Стан рахуємо з історії, нічого не зберігаємо:** вікно зараз, угоди/стопи сьогодні, рівень ризику (`lib/playbook/engine.ts`). Ліміти й ризик — **по рахунку**. Беззбиток (|R| < 0.1) нейтральний; «2 прибуткові на 0.5 %» — сумарно, не обов'язково підряд.
- **План угоди** — таблиця `trade_plans`. Зберігається лише якщо пройдено всі пункти чекліста (`planGate`); та сама функція працює в браузері (неактивна кнопка + перелік блокерів) і на сервері (`POST /api/trade-plans` перераховує вікно, ліміти, ризик своїм годинником і даними; 422 з переліком). CHECK-обмеження в БД — останній рубіж. Збережений план не редагується: лише «скасувати» (лімітка не спрацювала), прив'язати/відв'язати угоду, видалити скасований.
- **Ліміт дня** рахує угоди дня + активні плани дня, яким ще не знайдено угоду (угода імпортується пізніше).
- **План ↔ угода — на льоту** (як ADR 0014): рахунок, символ без суфікса брокера, напрямок, вхід від −5 хв до +8 год від плану, ціна в межах 30 % відстані до стопу; найближчі пари першими; ручна прив'язка має пріоритет. Імпорт CSV і Bridge **не змінено**.
- **Дисципліна угоди:** автоматично — немає плану, поза вікном, понад ліміт угод, після ліміту стопів, RR < мінімуму, ризик не за правилом, таргет далі за ціль плану, ручне закриття в 0 (`meta.bridge.close_reason = manual`). Вручну — `journal_trades.meta.discipline` (перенесений таргет, ранній БУ, часткова фіксація, модель лише на M3, …; тег «застій»; виняток ризику «добір / метали»). «За планом» = є план і жодного порушення. Стара ручна позначка `meta.review.followed_plan` не змінюється й лишається в «Розборі дня».
- **Головна:** віджет «ТС зараз» і метрики дисципліни (тиждень/місяць, за планом проти поза планом, застій) — над P&L.

## Наслідки
- Без міграції сторінка Playbook працює (правила, стан, автопозначки), а плани показують «міграцію не застосовано»; API відповідає 503 `available: false`.
- Стратегії «Контролю стратегії» дублюють частину чисел (3/2, RR 2). Залишено свідомо: стратегії — аналіз після факту по рахунку. Синхронізація «Playbook → правила стратегії» — після рішення власника.
- Скрін у плані — посилання (як `screenshot_url`), не завантаження файлу.
