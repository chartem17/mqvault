# Документація MQVault

Почніть із [architecture/overview.md](architecture/overview.md): шари, карта `src/`, ключові правила. Поточний стан робіт — [roadmap/ROADMAP.md](roadmap/ROADMAP.md).

## Структура

| Тека | Що там | Коли змінювати |
|---|---|---|
| [`architecture/`](architecture/) | Як побудовано систему: [огляд і карта коду](architecture/overview.md), [база даних і міграції](architecture/database.md) | Коли змінюється структура коду, схема БД чи залежності між шарами |
| [`decisions/`](decisions/) | ADR — ухвалені рішення й причини (час, сесії, фінанси, проп, видалення, доступ, мови, адаптивність, дашборд) | Нове рішення = новий файл; старе не стирати, а позначати `Замінено` |
| [`features/`](features/) | Як працює конкретна фіча: [проп-рахунки](features/prop-rules.md), [видалення з Undo](features/undo-deletion.md), [мови](features/i18n.md) | Разом із кодом фічі |
| [`roadmap/`](roadmap/) | [ROADMAP](roadmap/ROADMAP.md) — що зроблено, що далі, порядок і правила статусів | Після кожного завершеного пакета роботи |
| [`runbooks/`](runbooks/) | Ручні перевірки й інструкції: [приймання проп-системи](runbooks/prop-acceptance-checklist.md) | Коли змінюється процедура |
| [`archive/`](archive/) | Історичні журнали, які вже не керують роботою | Лише додавати |

## Правила

- **Одна істина.** Факт живе в одному місці, решта дає посилання. Правило поведінки — в ADR; як воно реалізоване — у `features/` або `architecture/`.
- **Код — первинний.** Якщо документ розходиться з кодом, виправляють документ; шлях до файлу в документі має існувати (`rg` по репозиторію перед комітом).
- **Статуси чесні.** `[x]` у roadmap означає «зроблено в указаному обсязі», а не «випущено» чи «прийнято в браузері».
- **Мова.** Документи для власника — українською; технічні інструкції, що живуть поряд із англомовним кодом (наприклад, `features/i18n.md`), можуть бути англійською.
- **Секретів тут немає.** Ключі, паролі та `.env` у документи не потрапляють.
